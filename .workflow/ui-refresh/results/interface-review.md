# Interface review

Method: native WPF screenshot/source review. The Impeccable web detector has no
verdict on XAML; Windows captures are the visual proof. The user's chat captures
and v5.0.5 frames establish the incumbent. The user explicitly selected white
for light mode and dark gray for dark mode, replacing the previous glows.

| Before | After | Why |
| --- | --- | --- |
| Slogans, eyebrow labels and decorative colored fields | Literal page names, neutral surfaces, generated monitor/LUT identity | A calibration tool needs clear state and neutral surrounding color. |
| Dithering selector centered below its label with repeated explanation rows | Label and selector share one row; drawbacks below; context link opens Documentation | The setting is easier to scan and occupies less vertical space. |
| Not-assigned value styled like a third button | Plain status text beside consistent Edit/Remove actions | Distinguishes information from actions. |
| English/Russian-only long help and static language bindings | Ten complete catalogs and a live indexer binding | Avoids mixed-language screens after changing language. |
| Shortcut registration could partially replace the pair | Pair transaction, validation, rollback and capture lease | Prevents duplicate or failed changes from silently disabling another action. |
| Setup errors inside a hidden final step | Error panel outside the step panels | Errors remain visible when validation fails earlier. |

Copy review: remove filler; check claims and units against source/research;
then review phrasing, consistency and translations. No unmeasured performance
claim or universal madVR fullscreen fix is introduced.

Questions skipped: purpose and visual direction were explicit; the single theme
question was answered by the user. No additional design interview is needed.
